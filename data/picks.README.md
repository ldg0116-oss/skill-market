# data/picks.json 양식

`docs/picks.html`(추천 탭)은 이 파일을 읽어 만든다. 매주 `weeks` 배열에 묶음 하나를 덧붙이고 `python scripts/build_lab.py`로 페이지를 다시 만든다. 지난 주 묶음은 지우지 않는다(화면의 '지난 추천'에 접혀서 보인다).

```json
{
  "nextUpdate": "2026-11-30",
  "schedule": "매주 월요일",
  "weeks": [
    {
      "date": "2026-11-23",
      "summary": "이번 주 추천을 한 줄로 (없어도 됨)",
      "shortReason": "5개에 못 미쳤을 때만: 왜 모자랐는지",
      "items": [
        {
          "name": "스킬 이름",
          "url": "원본 주소 (https://…)",
          "source": "올린 곳 (계정/저장소 또는 사이트)",
          "kind": "신규 | 새 버전 | 뒤늦게 발견",
          "published": "YYYY-MM-DD 또는 비움",
          "checked": "YYYY-MM-DD (확인한 날)",
          "field": "글·SNS | 엑셀·문서 | 조사·학습 | 홈페이지",
          "level": "화면 조작 중심 | 추가 설정 필요",
          "use": "어떤 업무에서 무엇을 만들 수 있다고 설명하는지 한 문장",
          "why": "이번 주에 시험해 볼 가치 한 문장",
          "scores": { "fit": 0, "prep": 0, "testable": 0, "transparent": 0, "korea": 0, "novel": 0 },
          "prep": "필요한 환경·계정·도구·설정 단계",
          "prepTime": "예상 준비 시간",
          "data": "어떤 자료를 넣고 어디로 보내는지, 파일 수정이나 외부 게시 권한이 필요한지",
          "test": "최소 시험안: 민감정보 없는 입력, 기대 결과, 비교할 기존 방식, 중단 조건",
          "testTime": "예상 검증 시간",
          "verify": ["검증에서 확인할 것 1", "검증에서 확인할 것 2"],
          "question": "블로그에서 답할 질문 하나",
          "unknown": ["미확인 사항"],
          "evidence": [{ "label": "근거가 된 문서 이름", "url": "https://…" }],
          "popularity": "별 수·설치 수 (참고용, 점수에 넣지 않음)"
        }
      ],
      "held": [{ "name": "보류하거나 거른 것", "reason": "이유" }]
    }
  ]
}
```

## 규칙

- `scores`의 여섯 항목은 각각 0~4점이다. 실제 업무 적합성 `fit`(25), 비개발자 준비 부담 `prep`(20), 검증하기 쉬운 정도 `testable`(20), 문서와 동작의 투명성 `transparent`(15), 한국 사용자에게 설명할 가치 `korea`(10), 기존 후보와의 차이 `novel`(10). 총점은 화면이 `점수 ÷ 4 × 비중`을 더해 계산하므로 따로 적지 않는다.
- 공개 문서와 공개된 수치에서 직접 읽은 것만 적는다. 모르는 칸은 비워 두거나 '미확인'이라고 적는다. 지어내지 않는다.
- 써 봐야 아는 것(실제 작동, 한국어 품질)은 평가하지 않고 `verify`에 적는다.
- `items`는 추천 순서대로, 5개까지 넣는다. 5개가 안 되면 있는 만큼만 넣고 `shortReason`에 이유를 적는다.
- 이 사이트는 공개 사이트다. 운영자의 개인 정보나 내부 메모를 넣지 않는다.
